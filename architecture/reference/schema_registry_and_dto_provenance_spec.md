# Schema Registry Resolution & DTO Reflection Field Provenance Specification

## 1. Executive Summary

This reference specification formalizes the exact deterministic provenance and runtime data flow of all metadata, schema definitions, and type trees exposed by `ed-schema` and resolved via `SchemaRegistry`.

Downstream components—including operator TUIs/GUIs, diagnostic observability probes, telemetry egress dispatchers, and connector hydration pipelines—require a verified, unambiguous ledger of where each field originates, what underlying mechanism extracts it, and how to query it without hardcoding or external assumptions.

## 2. Field Provenance Catalog

The following table itemizes every field surfaced during endpoint discovery and DTO tree rendering:

| Display / Log Field | Runtime Python Path | Immediate Source | Upstream Canonical Source | Derivation Mechanism |
| :--- | :--- | :--- | :--- | :--- |
| **Namespace** | `descriptor.key.namespace` | `SchemaKey.namespace` | `Manifest.name` | Declared in provider manifest contract. |
| **Endpoint Route** | `descriptor.key.endpoint` | `SchemaKey.endpoint` | `EndpointContract.route` | Declared in provider manifest contract. |
| **Discriminator Field** | `descriptor.key.discriminator_field` | `SchemaKey.discriminator_field` | `EndpointContract.discriminator_field` | Manifest declaration for 1:N polymorphic APIs (e.g. `$schemaRef` or `eventName`). |
| **Discriminator Value**| `descriptor.key.discriminator_value` | `SchemaKey.discriminator_value` | `EndpointContract.discriminator_value` | Manifest declaration for specific polymorphic route variant. |

| **Schema Title** | `descriptor.schema_definition.get("title")` | `SchemaDescriptor.schema_definition` | Canonical JSON Schema root (`title`) | Parsed directly from JSON schema file content. Fallback: filename stem. |

## 3. Detailed Data Flow Mechanics

### 3.1 Registry Resolution (`SchemaEngine.resolve_descriptor`)

1. **Resolution Key Construction:**
   ```python
   key = SchemaKey(
       namespace="eddn",
       endpoint="/approachsettlement-v1.0",
       discriminator_field=None,
       discriminator_value=None,
   )
   ```
2. **In-Memory Registry Lookup:**
   - Lookup takes place in $O(1)$ microseconds inside `InMemorySchemaRegistryAdapter` by matching the composite key tuple `(namespace, endpoint, discriminator_field, discriminator_value)`.
3. **Returned Payload:**
   - Yields a frozen `SchemaDescriptor`:
     - `descriptor.key`: The locator key.
     - `descriptor.schema_definition`: Complete in-memory dictionary of the raw JSON Schema.
     - `descriptor.model_cls`: Reference to the compiled Python dataclass type.
     - `descriptor.header_contract`: Ingested header requirements.

### 3.2 Dynamic Type Graph Reflection (`_render_dto_tree`)

To construct UI tree views, logging breadcrumbs, or deserialization schemas, consumers reflect upon `descriptor.model_cls` without needing hardcoded knowledge of child classes:

```python
import dataclasses
import typing
from typing import Any, get_args, get_origin


def inspect_dto_node(target_cls: type) -> dict[str, Any]:
    """Deterministically extracts field metadata and nested child models."""
    type_hints = typing.get_type_hints(target_cls)
    node_metadata = {
        "class_name": target_cls.__name__,
        "module": target_cls.__module__,
        "fields": {},
    }

    for field in dataclasses.fields(target_cls):
        resolved_type = type_hints.get(field.name, field.type)
        is_required = (
            field.default is dataclasses.MISSING
            and field.default_factory is dataclasses.MISSING
        )

        # Detect nested child dataclass
        if dataclasses.is_dataclass(resolved_type):
            child_info = inspect_dto_node(resolved_type)
            node_metadata["fields"][field.name] = {
                "type": "object",
                "required": is_required,
                "child": child_info,
            }

        # Detect list of child dataclasses
        elif (
            get_origin(resolved_type) is list
            and get_args(resolved_type)
            and dataclasses.is_dataclass(get_args(resolved_type)[0])
        ):
            item_cls = get_args(resolved_type)[0]
            node_metadata["fields"][field.name] = {
                "type": "array[object]",
                "required": is_required,
                "item_child": inspect_dto_node(item_cls),
            }

        # Primitive or union type
        else:
            node_metadata["fields"][field.name] = {
                "type": getattr(resolved_type, "__name__", str(resolved_type)),
                "required": is_required,
            }

    return node_metadata
```

## 4. Architectural Invariants for Downstream Applications

1. **Zero LLM / Dynamic Evaluation Dependency:**
   - All types, schema definitions, and metadata paths are guaranteed to be 100% deterministic, reproducible, and verifiable via static Python AST and JSON parsing.
2. **Immutable Runtime Contracts:**
   - Both `SchemaDescriptor` and generated dataclasses are strictly frozen (`@dataclass(frozen=True)`). Once ingested into the registry or instantiated, instances are side-effect free and thread-safe.
3. **Decoupled Boundary Presentation:**
   - UI views (TUI/GUI tables, trees) and logging formatters must query `SchemaDescriptor` and `model_cls` via standard reflection, maintaining complete decoupling from provider-specific implementation details.
